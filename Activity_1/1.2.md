# Task 1.2 — Work Plan

## 1. Development Strategy

### 1.1 Overall approach

- **Agile and iterative.** We use a lightweight Agile approach.
- We do not follow the full Scrum framework.
- Instead, we plan the project in stages and short iterations, reviewing the remaining work at the end of each stage.

During M2, we used a lightweight branch-based workflow.
Each issue was developed on a corresponding issue branch and later merged into the main branch.

In M3, we worked in short iterations of approximately one to three days.
In each iteration, we prioritised the highest-priority remaining tasks.

- **Why there is no M1 milestone in GitLab.** 

Our GitLab milestones begin with M2 because M1 was the initial design stage of the project. During M1, we discussed the gameplay as a group and created an initial game skeleton, now recorded as the Activity 1.1 deliverable in [Activity_1/1.1.md](1.1.md), which points to the full user-story catalogue.  
This stage mainly consisted of group discussions and shared design documents rather than implementation work, so it was not tracked through individual GitLab issues. Therefore, we did not create a separate M1 milestone.  
M2 to M6 cover the implementation, integration, testing, documentation and final submission stages after the initial design.

- Bugs and improvement ideas discovered during development were added as new issues to the relevant milestone, just like planned tasks.
### 1.2 Stages as GitLab milestones

Each project stage is represented by a GitLab milestone with a defined date range.
All issues are assigned to a milestone, so the milestone page provides an overview of the progress of each stage.

### 2.1 Order of work

The **Prerequisites** column in Section 3 gives the exact dependencies. In short, the work follows this dependency order:


```text
Collision and maps
  → Health → Combat pipeline
    → Classes and skills, enemy AI → Boss → Elemental reactions
      → Quest-gated battles and battle results
        → NPC dialogue and quests, inventory rewards (these need battle results)
          → Save / load (needs snapshots from every module, so it comes last)
```
