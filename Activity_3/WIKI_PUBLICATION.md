# Wiki publication checklist

The `wiki/` directory contains the English source copies of the COMP6120 GitLab Wiki. They were synchronized with Wiki commit `e605b9d` and reviewed against team `main` commit `7fea86a` on 3 October 2026.

## Publish safely

1. Open the team repository Wiki, not the personal fork's Wiki.
2. Inspect existing pages and their edit history. Preserve teammate content added after the synchronization point when incorporating later drafts.
3. Copy each Markdown file into the corresponding page, keeping its spelling/slug. `home.md` is Home; `_sidebar.md` is the custom navigation sidebar if enabled in this GitLab instance.
4. Preview each page, save with an explanatory Wiki commit message, and check internal links using the actual generated page URLs.
5. Upload real game screenshots and insert the Markdown generated by GitLab into Features. Local filesystem paths do not work as shared Wiki attachments.

## Required visual evidence

Capture the build being submitted. Suggested captions:

| Screenshot | Caption / evidence |
| --- | --- |
| Hub | Hub NPC services and the configurable portal. |
| Battle | A guardian encounter showing player abilities and Boss status. |
| Merchant upgrades | Shared core balance and equipment capped at +2. |
| Manage saves | Independent automatic/manual load and delete actions with Sydney timestamps. |
| Training | Damage and movement metrics used to compare equipment. |
| Expanded map | NPC labels and player/target markers. |
| Test/CI result | Commit-specific build result and JUnit test report. |

The published Features page contains current-build screenshots of the Hub, expanded NPC map, equipped inventory, merchant upgrade screen and save manager. Game Tester contains a real GitLab test-report screenshot and links the latest successful main pipeline. Battle, Training, title-menu, ending and debug-console screenshots remain useful optional evidence before final submission.

## Before final submission

- Confirm the submitted team main still contains the documented functional baseline and corrected `LICENSE.md`.
- Review teammate Wiki edits made after Wiki commit `e605b9d` before republishing these source copies.
- Link the final submitted revision's successful pipeline in Game Tester; replace the earlier CI screenshot if a final-report screenshot is captured.
- Keep the published Wiki and these source copies synchronized after later edits.
- If Docker or a standalone tester is added, update the corresponding pages and their limitations together.
- Add measured coverage if available; do not infer it from test counts.
- Verify the issue/MR links with the signed-in team account and ensure assessors can access linked evidence.

The Wiki is a separate Git repository. A code-repository commit of these source files alone does not satisfy the requirement to publish a GitLab Wiki.
